# Веб-пульт трактора

Локальный сервис для macOS, RF-Nano и проверенной модели Huina 1594. Работает на
том Mac, к которому плата подключена по USB. GitHub используется для хранения
исходников; облачное размещение страницы не даёт доступа к локальной USB-плате.
Во время работы доступ в интернет, аккаунт и Python-пакеты не нужны.

## Требования и первая установка

Клонирование и установка Arduino-зависимостей описаны в
[основном README](../README.md). Нужны Python 3.9+, Arduino CLI и AVR core
`arduino:avr`. Для диагностических скетчей также установите библиотеку RF24.
Для native C++ проверок нужны Xcode Command Line Tools; frontend тесты используют
JavaScriptCore из macOS, если он доступен.

Проверенная RF-Nano использует **CE=D10, CSN=D9**. Профиль загрузки —
`arduino:avr:nano:cpu=atmega328` с новым загрузчиком. Разводку другой ревизии
нужно проверить перед использованием этой прошивки.

На новой плате установите прошивку перед обычным запуском. Совместимая плата,
настроенная ранее, не требует повторной загрузки при каждом открытии страницы.

## Запуск

Откройте двойным щелчком [Запустить пульт.command](../Запустить%20пульт.command).
Откроется браузер с адресом **http://127.0.0.1:8765**. Окно Терминала с сервисом
оставьте открытым. Чтобы остановить сервис, нажмите в нём `Ctrl+C`.

Из терминала, находясь в папке проекта:

```sh
python3 -B web_control/server.py --open-browser
```

Если порт занят другим приложением, можно выбрать другой адрес:

```sh
python3 -B web_control/server.py --port 8767 --open-browser
```

Скрипт двойного щелчка ищет Python 3.9+ в `PATH`, `~/.local/bin` и системном
каталоге. Если macOS не разрешает запуск `.command`, запустите команду выше из
Терминала. Файлы запуска должны иметь право исполнения:

```sh
chmod +x Запустить\ пульт.command Прошить\ плату.command
```

## Подключение и питание

1. Подключите RF-Nano к USB. Сервис автоматически обнаруживает плату и проверяет
   ответ прошивки. Если платы нет, веб-пульт показывает подсказку подключения.
2. Включите питание трактора и выключите штатный пульт. Отметьте в веб-пульте,
   что питание включено. Эта отметка — ваше подтверждение, а не показание датчика.
3. Нажмите и удерживайте нужную кнопку или клавишу. Отпустите для прекращения
   команды. Кнопка **СТОП**, пробел и `Esc` прекращают передачу.

При отключении USB, потере связи со страницей, переключении вкладки или потере
фокуса активная команда прекращается. После восстановления соединения требуется
новое нажатие. Сервис сбрасывает подтверждение питания после переподключения
платы. В интерфейсе отдельно видны состояние платы и напоминание о питании модели.

Старую экспериментальную прошивку сервис распознаёт и просит заменить. Для этого
остановите сервис и запустите [Прошить плату.command](../Прошить%20плату.command).
В окне запущенного сервиса нажмите `Ctrl+C`: скрипт прошивки не останавливает
его автоматически. Arduino CLI ищется в `PATH` и `~/.local/bin`. Если найдено
несколько USB-портов, выберите порт аргументом:

```sh
./Прошить\ плату.command /dev/cu.usbserial-ИМЯ_ПОРТА
```

Без аргумента выбирается единственный `cu.usbserial-*` или `cu.wchusbserial*`.
Загрузка прошивки сама по себе не запускает движение.

Для сервиса при нескольких подключённых платах порт тоже можно задать явно:

```sh
python3 -B web_control/server.py --serial-port /dev/cu.usbserial-ИМЯ_ПОРТА --open-browser
```

## Управление

| Действие | Клавиша |
|---|---|
| Обе гусеницы вперёд | `W` |
| Левая вперёд / назад | `Q` / `A` |
| Правая вперёд / назад | `E` / `D` |
| Башня влево / вправо | `J` / `L` |
| Основная стрела вверх / вниз | `I` / `K` |
| Остановить передачу | `Space` / `Esc` |

За один раз выполняется одна команда. Непроверенные сочетания направлений и
управление снятым ковшом не добавлены. Для опускания стрелы используется отдельно
проверенный шаблон `70`, а не прежний `72`.

## Проверка без модели

```sh
python3 -B web_control/server.py --demo --port 8766 --open-browser
```

В демонстрационном режиме USB не открывается и радиопередачи нет. На странице
показана пометка демонстрации. Режим предназначен для проверки кнопок, клавиатуры
и уведомлений, а не для управления трактором.
Счётчики деморежима по умолчанию хранятся в памяти, отдельно от реального пульта.

## Технические сведения

Backend использует стандартную библиотеку Python 3.9+, frontend — локальные
HTML/CSS/JavaScript. Сервис слушает только loopback-адрес этого компьютера;
команды защищены проверками Host, Origin и токеном страницы.

Новая прошивка [rf_nano_controller](../rf_nano_controller/) разрешает только
девять проверенных действий. Она отключает передатчик при отсутствии heartbeat
100 мс и ограничивает отдельный запуск одной секундой и 200 кадрами. Долгое
удержание в браузере состоит из отдельных запусков с новыми счётчиками; сервис
не выполняет очередь движений. Свежесть удержания проверяется на стороне сервиса.

Состояние счётчика сохраняется в `web_control/runtime/state.json` перед отправкой
команды. Журналы экспериментов и [каталог команд](../rf_nano_tx_test/control_catalogue.json)
сохранены отдельно. Не запускайте экспериментальные serial-инструменты одновременно
с веб-сервисом. При возврате к ним учитывайте новый счётчик веб-сервиса.

`runtime/state.json` — локальный файл, он не входит в Git. При переносе управления
той же моделью остановите старый сервис и перенесите актуальный файл счётчиков
на новый Mac в тот же относительный путь. Без него первое состояние берётся из
`web_control/config.json` (поле `initial_counter_hex`): это начальное значение
для новой локальной установки, а не автоматически определённый текущий счётчик.
Существующий `runtime/state.json` остаётся главным источником состояния. После
работы штатного пульта или изменения состояния модели актуальность счётчика
нужно проверить. Локальные журналы прежних сеансов не входят в публичную версию.

Плата не получает подтверждения от трактора. Сервис может установить наличие
USB-платы и исправность ответа её прошивки, но не определяет питание модели,
фактическое движение или завершённую привязку после перезапуска. Если модель не
реагирует, проверьте питание и работоспособность штатной связи; процедура
автоматической привязки пока не реализована.

## Проверки

Из корня проекта:

```sh
python3 -B -m unittest discover -s web_control -p 'test_*.py'
python3 -B web_control/tests/test_frontend.py
python3 -B rf_nano_controller/tests/verify_packets.py
python3 -B rf_nano_controller/tests/verify_captured_fixtures.py
```

Проверки сервиса используют имитацию последовательного порта и локальный HTTP.
Они проверяют удержание, STOP, потерю lease, счётчики, отключение и повторное
подключение. Frontend проверяется с моделями DOM/HTTP/таймеров; при отсутствии
JavaScriptCore эта проверка пропускается. Генератор радио проверяется независимым
декодером на 864 кадрах. Эти команды не загружают прошивку и не передают RF.
